# Run Tests

<webui-page-segment>

## Commands

Run every test: the unit tests (Vitest, about 20 seconds), then the browser tests (Playwright). Both test the minified files sites load

```pwsh
npm test
```

Run only the unit tests, which cover most of the framework in a simulated page. A test that passed before is skipped while nothing it depends on has changed (results are kept in `.test-cache/unit`, which is committed)

```pwsh
npm run test:unit
```

Run every test, ignoring the unit test cache

```pwsh
npm run test:full
```

Watch the unit tests, running the ones a change affects

```pwsh
npx vitest
```

Run only the browser tests: layout, real media, mouse, scrolling, and navigation

```pwsh
npm run test:browser
```

Open the interactive runner for the browser tests, with watch mode and a timeline for each test

```pwsh
npm run test:ui
```

Open the last browser test report, with a screenshot and trace for each failure

```pwsh
npm run test:report
```

Run one unit test file, or one browser test file

```pwsh
npx vitest run tests/unit/components/alert.test.mjs
npx playwright test tests/browser/components/drawer.spec.mjs
```

Run tests by name

```pwsh
npx vitest run -t "webui.clone"
npx playwright test -g "webui.clone"
```

## Stress tests

Once a week, for each project worked on that week, run the tests the week's changes affect many times each under heavy load. A test that fails here only some of the time is a timing race to fix. This never runs as part of a normal test run, Publish, or CI. With nothing changed in the last 7 days it says so and runs nothing.

```pwsh
pwsh ./PowerShell/StressTests.ps1
```

Stress every test, whatever changed

```pwsh
pwsh ./PowerShell/StressTests.ps1 -All
```

Look back further, or run each test more or fewer times

```pwsh
pwsh ./PowerShell/StressTests.ps1 -Days 14 -Repeat 5
```

## Test files:

- `tests/components/` has one file per component, named after its file in `cdn/webui/`.
- `tests/methods/` covers the `webui.*` methods and `webui.define`.
- `tests/loader/` covers data binding, routing, clicks, and real site pages.
- `tests/coverage.spec.mjs` fails when a component or `webui.*` member has no tests, and names what is missing.
- `tests/support/webui.mjs` provides `test`, `expect`, and `mount(page, html)`.

Any uncaught error during a test fails that test, even if its checks pass.

A test marked `test.fail(true, 'Known bug: ...')` documents a bug that has not been fixed yet. Once the bug is fixed the test reports `Expected to fail, but passed`, which is the cue to delete that line.

# Test Dependencies

<webui-page-segment>

Unit tests use [Vitest](https://vitest.dev) with [jsdom](https://github.com/jsdom/jsdom), and browser tests use [Playwright](https://playwright.dev). Neither needs a running server, since both serve files directly from `cdn/`. Nothing leaves your machine during a test run.

```pwsh
npm install
npx playwright install chromium
```

On Linux the tests use `/usr/bin/chromium` if it exists, so the second command can be skipped. Set `PW_CHROMIUM_PATH` to use a different browser.

</webui-page-segment>
